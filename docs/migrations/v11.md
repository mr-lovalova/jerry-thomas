# Migrating to v11

Jerry Thomas 11.0.0 removes the previous configuration syntax without aliases
or automatic conversion. Update project configuration and scripts before upgrading.

| v10 | v11 |
| --- | --- |
| Source stream `ordered_by: [ticker, time]` | `presorted: true` |
| Build profile/defaults `mode` | `artifact_mode` |
| Artifact mode `AUTO` | `auto` |
| Artifact mode `FORCE` | `rebuild` |
| Artifact mode `OFF` | `require_current` |
| `observability.visuals: ON` / `OFF` | `true` / `false` |
| CLI `--visuals on` / `--visuals off` | `--visuals` / `--no-visuals` |

## Stream ordering

```yaml
partition_by: [ticker]
presorted: true
```

`presorted` defaults to `false`. Set it to `true` only when records after mapping
and preprocessing already follow the partition fields in declaration order,
then `time`. Without partition fields, the required order is just `time`.
Jerry validates the guarantee while streaming; an out-of-order record fails the
pipeline. With `false`, Jerry sorts the records. The old `ordered_by` field is
rejected even when `presorted` is also supplied.

## Artifact policy

```yaml
# profiles/build.defaults.yaml
artifact_mode: auto
observability:
  visuals: false
```

Use `artifact_mode` in build profiles and build defaults. Build profiles override
build defaults, and `jerry build --force` still explicitly requests a rebuild.
For serve, inspect, and materialize, the policy remains command-wide: set it in
`<command>.defaults.yaml` or pass `--artifact-mode` on the CLI.

The values are exact, lowercase strings:

- `auto` builds missing or stale artifacts and reuses current artifacts.
- `rebuild` rebuilds the selected dependency closure.
- `require_current` performs no builds and fails when required artifacts are
  missing or stale.

Old spellings, including lowercase `force` and `off`, are rejected. No value
needs YAML quoting.

## Visuals and booleans

Visual settings use booleans throughout the configuration and Python runtime
settings. `null` or omission means inherit the setting; the built-in default is
`true`. Explicit `false` overrides an enabled default.

Use `--visuals` to enable visuals and `--no-visuals` to disable them. The old CLI
value arguments and visual configuration strings are rejected. YAML boolean
resolution recognizes `true` and `false` (case-insensitively); words such as
`on`, `off`, `yes`, and `no` are strings, so they cannot bypass strict validation.

## Versions and artifacts

The package version is `11.0.0`. The `project.yaml` header remains
`schema_version: 6`: its structure has not changed. Do not replace this with 11.

Stream configuration participates in artifact fingerprints, so the new
`presorted` field changes fingerprints. Run with `auto` or `rebuild` to prepare
current artifacts before using `require_current`. This migration does not
require incrementing `artifact_revision` solely for these configuration edits.

## Saved runs

New serve runs write `run.json` with `schema_version: 1` and an `outputs` list
describing completed files, their formats, row counts, and fold identities.
The required `split` field saves the resolved split configuration from before
execution, or `null` for an unsplit project. Fold output metadata is validated
against these saved rules. Early v11 development manifests without `split` must
be regenerated; the initial released manifest schema remains version 1.
`jerrythomas.io.runs.load_run()` selects saved outputs without the current project
configuration. It rejects unversioned manifests; generate a new v11 run instead
of inferring metadata from legacy filenames. See [reading saved runs](../research.md#read-a-saved-run).

The completed invocation API (`ServeRunResult.outputs` and `--result-json`)
continues to return paths.
