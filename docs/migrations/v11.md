# Migrating to v11

Jerry Thomas 11.0.0 removes the previous configuration syntax without aliases
or automatic conversion. Update project configuration and scripts before upgrading.

| v10 | v11 |
| --- | --- |
| Source stream `ordered_by: [ticker, time]` | `presorted: true` |
| Build profile/defaults `mode` | `artifact_mode` |
| Artifact mode `AUTO` | `auto` |
| Artifact mode `FORCE` | `rebuild` |
| Artifact mode `OFF` | `require_current` |
| `observability.visuals: ON` / `OFF` | `true` / `false` |
| CLI `--visuals on` / `--visuals off` | `--visuals` / `--no-visuals` |

## Stream ordering

```yaml
partition_by: [ticker]
presorted: true
```

`presorted` defaults to `false`. Set it to `true` only when records after mapping
and preprocessing already follow the partition fields in declaration order,
then `time`. Without partition fields, the required order is just `time`.
Jerry validates the guarantee while streaming; an out-of-order record fails the
pipeline. With `false`, Jerry sorts the records. The old `ordered_by` field is
rejected even when `presorted` is also supplied.

## Artifact policy

```yaml
# profiles/build.defaults.yaml
artifact_mode: auto
observability:
  visuals: false
```

Use `artifact_mode` in build profiles and build defaults. Build profiles override
build defaults, and `jerry build --force` still explicitly requests a rebuild.
For serve, inspect, and materialize, the policy remains command-wide: set it in
`<command>.defaults.yaml` or pass `--artifact-mode` on the CLI.

The values are exact, lowercase strings:

- `auto` builds missing or stale artifacts and reuses current artifacts.
- `rebuild` rebuilds the selected dependency closure.
- `require_current` performs no builds and fails when required artifacts are
  missing or stale.

Old spellings, including lowercase `force` and `off`, are rejected. No value
needs YAML quoting.

## Visuals and booleans

Visual settings use booleans throughout the configuration and Python runtime
settings. `null` or omission means inherit the setting; the built-in default is
`true`. Explicit `false` overrides an enabled default.

Use `--visuals` to enable visuals and `--no-visuals` to disable them. The old CLI
value arguments and visual configuration strings are rejected. YAML boolean
resolution recognizes `true` and `false` (case-insensitively); words such as
`on`, `off`, `yes`, and `no` are strings, so they cannot bypass strict validation.

## Versions and artifacts

The package version is `11.0.0`. The `project.yaml` header remains
`schema_version: 6`: its structure has not changed. Do not replace this with 11.

Stream configuration participates in artifact fingerprints, so the new
`presorted` field changes fingerprints. Run with `auto` or `rebuild` to prepare
current artifacts before using `require_current`. This migration does not
require incrementing `artifact_revision` solely for these configuration edits.

## Saved runs

Serve and materialize use the same receipt schema, version 2, and return
`SavedRun` objects from `run_profiles()`. This replaces the early v11
`ServeRunResult`, `MaterializeRunResult`, and `MaterializedOutput` types.
Use `result.metadata.run_id`, `result.metadata.preview`, `result.metadata_path`,
and `result.outputs`; descriptors are in `result.metadata.outputs`.

Serve retains `run.json` in each run directory. Materialize automatically saves
`<output filename>.run.json` beside each output. `load_run()` accepts either a run
directory or a receipt file. Early version-1 manifests must be regenerated.

Both commands' `--result-json` output uses envelope version 2. Each entry contains
an absolute `receipt` path and the shared manifest fields; output paths are now
relative to the receipt's directory. The required `split` field retains serve's
resolved split rules, and fold metadata is validated against those rules.
Materialize receipts identify the source stream with `stream` and use `null` for
split and fold metadata. See [reading saved runs](../research.md#read-a-saved-run).

## Period aggregation

Use `resample` for fixed or calendar-month aggregation. The demo equity streams use it
instead of `floor_time` followed by `collapse`. Results are labeled at the
exclusive period end and contain only partition keys and explicit aggregates;
for example, January observations produce a record at February 1. Empty covered
periods remain visible as null records. Specify coverage bounds to include
complete first and last periods. Rebuild artifacts after migrating streams.

`round_time` handles timestamp normalization; `collapse` remains same-key record
selection. See [resampling](../transforms/stream.md#resampling) for the unified API.
Synthetic time streams use their source ticks directly: encoding a timestamp
does not require aggregation, flooring, or gap filling.

## Timestamp rounding

Replace `operation: floor_time` with `operation: round_time` and add
`direction: floor`. Use `direction: ceil` to round up instead. Direction is
required; the old operation name is rejected. Both directions preserve every
record and leave exact-grid timestamps unchanged. Python callers use
`RoundTimeConfig` and `RoundTimeTransform` with the same required direction.

## Explicit sample rounding

Every dataset must choose `sample.rounding`; there is no default:

```yaml
sample:
  cadence: 1h
  rounding: floor  # floor, ceil, or exact
```

`floor` preserves the original start-labeled buckets: `[10:00, 11:00)` maps to
10:00. `ceil` uses `(10:00, 11:00]` labeled 11:00. `exact` rejects off-grid
observations, including sequence warmup records. Aligned timestamps are unchanged.
Choose the convention together with the prediction cutoff, target alignment,
and horizon measured from the sample key; neither rounding direction alone
establishes data availability. Stream timestamps remain unchanged.

Features, targets, sequence endpoint assignment, collection, preview grouping,
and scaler training share the selected policy. Multiple values assigned to one
sample still require explicit `collect` or upstream aggregation. Collection size
is checked after assignment; incomplete populated buckets fail rather than drop.

Rebuild artifacts: cache semantics and series manifests are now version 13
(the package remains v11). Manifests store the rounding policy, and reuse with a
different dataset policy is rejected. Missing settings and old manifests fail;
there is no compatibility fallback to implicit floor or ceil.
