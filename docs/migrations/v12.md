# Migrating to v12

v12 uses project schema 7. A project owns shared source and stream catalogs,
named datasets, operations, and profiles. The old schema and workspace aliases
are rejected; source and stream syntax is unchanged.

1. Rename workspace routing keys in `jerry.yaml`:

   ```yaml
   projects:
     research: research/project.yaml
   default_project: research
   ```

   Use `--project research`, a project folder, or a `project.yaml` path.
   `--dataset` and `-d` are removed. Select an executable profile with `--profile`;
   omitting it still runs every enabled profile for the command.

2. Set `schema_version: 7` and replace `paths.dataset` with `paths.datasets`:

   ```yaml
   paths:
     sources: sources
     streams: streams
     datasets: datasets
     operations: operations
     artifacts: artifacts
     profiles: profiles
   ```

   Move `dataset.yaml` to `datasets/default.yaml`. The filename supplies ID
   `default`; add `version: v1`. Multiple dataset directories are supported.
   A stream-only project can omit `paths.datasets`.

3. Declare runtime operations explicitly:

   ```yaml
   # operations/dataset.yaml
   kind: runtime
   entrypoint: core.runtime.dataset
   dataset: default
   ```

   Existing `operation: dataset` profiles can keep that binding. Declare
   coverage and matrix operations similarly with `core.runtime.coverage` and
   `core.runtime.matrix`. Every operation file supplies its `kind` and
   `entrypoint`; its filename supplies the operation ID.

4. Update build profiles to generated dataset artifact IDs such as
   `dataset.default.series`, `dataset.default.metadata`, or
   `dataset.default.scaler`. An explicit artifact override declares its dataset,
   kind, and entrypoint; profiles reference that override's own filename ID.
   Rebuild artifacts after migration.

5. Put scaler settings beside each scaled feature or target:

   ```yaml
   features:
     - id: price
       stream: equity.prices
       field: close
       scale:
         with_mean: false
         with_std: true
         epsilon: 1.0e-12
   ```

   `scale: true` and `scale: {}` use the built-in defaults (`with_mean: true`,
   `with_std: true`, `epsilon: 1.0e-12`); omitted or `false` disables scaling.
   Move non-default settings from the old scaler operation, or an earlier v12
   dataset-level `scaling` block, into each affected `scale` mapping. Remove the
   old settings; neither location is accepted. Rebuild scaler artifacts.

6. Replace a materialize profile's `stream` with an operation reference:

   ```yaml
   # operations/prices.yaml
   kind: runtime
   entrypoint: core.runtime.stream
   stream: equity.prices

   # profiles/materialize.prices.yaml
   operation: prices
   output: exports/prices.jsonl.gz
   ```

7. Update CLI flags: replace `jerry build --force` with
   `jerry build --artifact-mode rebuild`, and replace materialize's `--output`
   with `--output-file`. Long options no longer accept abbreviations.
   Project-targeted scaffolding accepts `--project` after `source create`,
   `stream create`, or `inflow create`.

Profiles keep output destinations and execution policy. Dataset-bound profiles
can interpolate `${dataset_id}` and `${dataset_version}` in output settings;
these do not change the shared stream catalog. Relative configuration paths
remain relative to `project.yaml`.

Python integrations require explicit selection:
`iter_samples(project, dataset="default")` and
`iter_model_batches(project, dataset="default")`. Add `output_id` as before for
split datasets.

Use `jerry list datasets`, `jerry list streams`, and `jerry list profiles` with
`--project` to inspect the migrated catalog and bindings.
